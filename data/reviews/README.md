# 每日与阶段学习记录

日报使用朱批录的本地 JSON 结构思路；本项目不调用其 `update_daily.js`，因为该脚本重复执行会重复增加累计学习天数。原始记录放在 `data/tracker/daily/YYYY-MM-DD.json`，个人统计从这些记录重算，不读取 `stats_cache.json`。通过 `scripts/record_daily.py` 执行幂等写入。

每条练习批次应包含：

- `event_id`：该次汇报的稳定唯一编号。优先使用用户提供的套题/批次名称；没有名称时由日期、科目、题量、错题数和原始备注形成确定键。相同输入重放时更新原条目，不新增次数；用户明确说是独立二次训练时另建事件。
- `exam_type`、`province`、`year`、`paper_type`：未知写 `null`，不从题型风格推断。
- `source` 与 `source_type`：区分官方真题、已核验真题整理、培训模拟、AI 原创或未核验材料。
- `modules`：只记录用户实际报告的题量、错题数、用时。
- `recorded_at`、`note`：保留记录时间与用户提供的必要备注，不保存无关隐私。

错因的通用分类沿用任务书：知识点不会、概念混淆、公式记错、方法选择错误、推理错误、审题遗漏、计算错误、选项辨析不足、时间控制问题、猜对或侥幸做对、待确认。Skill 的细分标签可作为解释保留；没有用户作答过程或明确确认时，通用分类只能是“待确认”。

日常自然语言操作时由 Codex 组装这些字段并调用本地写入脚本；同一事件如果补充或更正资料，应沿用原 `event_id`，脚本会原位更新该事件。如果另做一套即使题量和错题数相同，也要给独立的批次名称或 `event_id`。

套题汇总与 xingce 单题错因卡是不同粒度。日报提供一次整套的题量/错题统计，错因卡提供题目与复盘；统计某一范围时只能选择一个粒度的来源，不能把两者的错误数相加。复练结果记为独立复习事件，不覆盖首次作答。

没有真实日报时，日报/周报应报告“暂无记录”，不以验收用例或 Skill 示例填充学习天数、正确率或能力变化。
